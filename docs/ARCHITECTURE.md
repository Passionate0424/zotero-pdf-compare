# 架构设计草案

状态：设计待原型验证，不代表已实现。

## 组件

`Zotero 插件 → 本机辅助程序 → 独立 Chrome / 豆包网页 → PDF 临时结果 → 插件验证与导入`

- addon：Zotero 菜单和工具栏、模式控制器、原文阅读器扩展、译文窗格、同步、附件配对与导入。
- worker：独立持久浏览器配置、豆包页面操作、串行队列、状态与下载。需要 Node/Playwright 运行环境，不能假定 XPI 自身提供 Node。
- shared：任务、进度、错误和结果类型；协议与实现分离，后续后端可扩展。
- runtime：仅本机使用，不提交或随发布包携带浏览器凭据。

本机服务只监听回环地址，插件与 worker 使用本机鉴别令牌。只接收登记任务目录中的文件；拒绝任意路径读取、任意 URL 代理与任意命令执行。端口与进程归属须检查，不根据端口开放就认为是本项目服务。

## 阅读器

首选保留 Zotero 创建并管理的原文宿主 ReaderInstance，让原生工具栏、批注、右键、笔记、标签、复制与拖拽继续走 Zotero 链路。插件增加译文窗格和联动监听，禁用时移除自身布局和监听。

原文附件身份不变，批注记录属于原附件。不把翻译 PDF 替换为原文，不重写原批注坐标，也不将批注作为插件私有数据保存。Zotero 只读权限原样遵守。

当前候选上游的双阅读器会重建宿主或使用只读配置，不能直接照搬满足上述要求。需要针对实际目标版本验证保留宿主的布局及生命周期；此项是 P1 主要交付。

三模式统一管理，但只有原文或译文的本体阅读位置由相应阅读器持有；插件记录模式、最近操作侧和对应页内锚点，避免同时出现多个相互独立的原文编辑器。

## 滚动同步

默认开启，可手动关闭。按最近真实输入的一侧作为来源，使用同页号和页内规范化位置映射，读取实时页面边界；两侧可具有不同缩放和宽度。页间空白与首尾单独夹取处理。

逐帧合并事件，标记程序写入以抑制反向触发。缩放和分隔条调整后，等待布局稳定并恢复锚点；文字选择、批注编辑不触发反向拉动。页数不匹配不得宣称精确同步，应要求对应页映射或显式近似模式。

## 任务模型

任务至少包含：jobId、libraryID、sourceAttachmentKey、sourceHash、targetLanguage、provider、conversationURL、stage、attempt、outputHash、translatedAttachmentKey、时间与结构化错误。禁止记录 Cookie、完整鉴别令牌或登录验证码。

阶段：排队 → 等待登录/上传 → 发送 → 预览 → 翻译与导出 → 下载 → 校验 → 导入 → 完成；另有失败与取消。翻译与导出可能交叠，以实际页面状态为准。

去重键基于来源库、附件、文件指纹、语言与后端。持久化源译文映射，不能把“最新 PDF”当作译文。已导入、下载成功未导入和导入中断三种状态需分别恢复。

PDF 使用解析器检查文件完整性、页数与页面尺寸；只检查扩展名或 `%PDF-` 不够。页数与页面布局匹配只证明位置映射基础，不证明翻译准确或内容完整。

取消时阻止后续导入并收束本任务资源，不关闭所有 Chrome 或 Zotero 进程。崩溃恢复先核对已有结果与附件，避免重复上传/归档。
