# Git 与里程碑管理

2026-11-01 用户授权开始开发。只管理本地 Git；未经用户明确授权不推送远程或发布。

## 版本规则

- `main` 保留可复现的阶段基线，阶段开发使用 `dev/p0-isolation` 等分支。
- 初始计划提交打 `baseline-plan` 标签。阶段所有必需条件通过后，合并阶段分支并打注释标签 `milestone/p0`、`milestone/p1` 等。
- 代码、测试、阶段报告和对应 WORKLOG 记录一起提交。敏感运行目录、数据库、登录状态、PDF 样本与构建物不提交；公开样本通过 URL 和 SHA-256 清单复现。
- 中途有未完成项可提交工作进度，但不能打完成标签。测试失败、未运行或人工待确认均不等于通过。
- 正式版本 `v0.1.0` 只有 P0–P5 必需条件通过且候选包有指纹时才生成，不把阶段原型当正式版本。

## 阶段完成条件

| 里程碑 | 主要判定 | 证据 |
| --- | --- | --- |
| P0：隔离基线 | 测试进程的实际 profile/data 确认；无同步和 Connector 串库；正式进程存活与保护文件未变；测试退出/重启、空库与快照校验 | 自动探针 JSON、进程记录、保护文件前后清单、快照与恢复检查 |
| P1：原生批注 | 对照中保留原生宿主；已有批注显示、创建/编辑/删除/标签/评论；笔记、复制与拖拽；重启和禁用后保留；权限正确 | 原生环境集成与交互验收记录，逐项状态 |
| P2：三模式同步 | 20 次切换无重复标签；双向滚轮/拖动/键盘/跳页；19 页对应；页内误差目标 ≤0.02；登记硬件至少 100 次延迟测量 P95 ≤100ms；批注不受干扰 | 几何误差与延迟样本、真实阅读器记录 |
| P3：豆包任务 | 3 次独立真实下载；登录恢复、取消、超时、去重；完整解析；无凭据泄漏 | 下载哈希、PDF 页数、任务事件与错误路径记录 |
| P4：完整归档 | 来源配对正确，多附件不误配；重试不重复；重启找回关联；原文和批注不变 | 隔离库端到端结果和数据库/API 断言 |
| P5：回退交付 | 禁用/卸载恢复原生；任务停止；准确识别新增附件；关闭状态备份与恢复演练；版本与候选包指纹 | 回退报告、恢复后附件/批注检查、支持版本清单 |

完整逐条检查以 [ACCEPTANCE.md](ACCEPTANCE.md) 为准。指标若实际无法达到，应记录测量证据并明确调整依据，不能静默放宽判定。

视觉 UI 测试为必需门槛：P0 留初始窗口证据，P1 验证原文/对照/批注 UI，P2 检查三模式、尺寸、主题与实际 DPI，P4 检查任务状态，P5 检查禁用恢复。脚本测试通过但缺少适用的真实截图及视觉检查时，不打阶段完成标签。逐项编号 UI-01–08 见验收清单。

`milestones.json` 为阶段状态登记；每阶段结果写入 `docs/reports/`，大文件和含本机信息的原始报告留在不提交的 artifacts/runtime。阶段完成标签必须对应可追溯的提交和验收摘要。
