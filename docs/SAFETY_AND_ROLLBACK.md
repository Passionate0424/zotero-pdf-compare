# 隔离与安全回退

## 开发边界

项目采用插件方式，不修改 Zotero 本体。默认复用已安装的程序，通过显式配置和数据目录启动开发实例；不需要另装一套 Zotero。正式环境只允许为确定版本和保护边界所需的只读检测，不向日常配置安装开发版或导入测试附件。可执行文件共享不等于配置和文献库共享。

具体搭建步骤见 [ENVIRONMENT_SETUP.md](ENVIRONMENT_SETUP.md)。卸载插件只会触发卸载和清理流程，不能自动撤销已导入附件、改写的文献或持久设置，不能替代测试库隔离。

计划目录（当前仅规划，测试环境尚未启动）：

```text
runtime/zotero-app/           可选：不同版本/调试构建时才使用
runtime/zotero-profile/       独立 Zotero profile
runtime/zotero-data/          独立数据库与附件 storage
runtime/browser-profile/     专用豆包登录状态
runtime/jobs/                翻译任务与临时文件
runtime/logs/                本机日志
runtime/backups/              测试快照与校验清单
```

所有路径预检应解析绝对路径、检查重解析点/目录链接，并与正式环境保护清单比对。测试进程必须显式使用独立 profile/data；不能默认启动、复用正式实例，或通过结束正式 Zotero 解决实例冲突。测试实例不得运行程序自动更新或修改默认应用关联，首次启动要核验 Word 等集成的安装副作用；不能控制这些副作用时重新评估隔离方式。

测试库关闭数据与文件同步，不复制正式 profile 中的账号、同步设置和完整库。公开样本复制到测试库，不直接使用正式 storage 或链接附件文件。

## 三种回退

1. **界面回退**：测试插件禁用/卸载时移除译文窗格、按钮、事件与计时器，恢复原生布局。原文宿主、批注和阅读器状态保持有效。
2. **任务与新增附件回退**：取消未完成任务，停止归档；依据 jobId 与持久化附件 key 清单定位新增译文。卸载不会自动删除文献或批注，也不能假设卸载即撤销所有数据库写入。
3. **测试环境快照恢复**：测试 Zotero 与 worker 完全退出后，备份独立配置和完整测试数据，记录文件清单、大小及哈希。恢复前保留故障现场，不直接覆盖唯一备份。

开发早期先在测试库演练第二、三种回退。正式库恢复不属于当前授权；未来如需恢复，应明确恢复点及之后新增数据的保留方案。

## 备份要求

- 完整备份在 Zotero 关闭、数据库连接退出后执行；不能只复制活跃的 zotero.sqlite 并宣称得到一致备份。
- 包含配置、数据库和 storage；如果未来正式使用涉及链接附件，需要将实际外部文件纳入范围，不能只备份 Zotero 数据目录。
- 记录目标版本、插件版本、时间、文件清单与校验值；至少验证一次恢复后的可打开性及附件/批注完整性。
- 备份可能含账号和隐私，只保留本机受控路径，不提交代码仓库或上传。

## 禁止的恢复方式

不删除正式 profile/data，不直接修改 Zotero 数据库，不自动迁移批注，不杀掉所有 Zotero/Chrome 进程，不通过整盘/整目录递归清理“重置”。所有删除与移动先验证最终目标，限定登记的项目内资源。

## 正式使用门槛

P0–P5 通过后给出候选包、测试报告与已知限制。安装正式环境前完成可验证备份并取得安装授权；在此之前，所有写入测试都留在隔离环境。
