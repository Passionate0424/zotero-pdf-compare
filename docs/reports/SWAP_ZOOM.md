# 左右互换与缩放区域同步

2026-11-02，独立开发版 0.3.1，Zotero 10.0.7，Windows，DPR 1.25。仅安装项目独立配置；main 保持 P1 基线，未发布。

## 行为

“互换”通过 CSS order 交换现有两个阅读器的位置，不重建或移动原文宿主 DOM；批注保留在原附件。交换时保留各文档原有宽度，分隔条仍按物理方向拖动，每次进入对照均分。两侧工具栏均可操作。

“同步缩放”默认开启，百分比使用同倍率，适应模式使用同预设。还同步当前页内视口中心的横向、纵向相对坐标，避免仅倍率相同但查看区域不同。开启滚动联动后，单独横向移动或上下滚动都会跟随；关闭滚动联动后，缩放瞬间仍同步倍率及区域，后续可各自浏览。关闭缩放同步可各自缩放。两个开关独立，左右顺序与缩放选择在本机配置保存。

这是几何对应，不是语义段落匹配；视口尺寸不同、页边界夹取和翻译排版变化会限制完全重合。原文始终可写，译文窗格只读。

## 调试证据与负结果

早期测试出现：关闭滚动后译文仍跳回初始位置，重新开启缩放时变为 page-width。监听原生 scalechanging 的调用栈显示：PDFView._setState → pdfViewer.scrollPageIntoView → currentScaleValue。安装目录本机原生源码确认 _setState 在 pagesPromise 后再次恢复初始位置，initializedPromise 在此之后才完成。原代码只等待 .page 节点，初始化未完成就暴露了同步。

检查点 2ec0b7ba17c49e1623367e8137e2f1fa4ee5b7dc。在 addon/src/main.js 等待两侧原生 PDFView.initializedPromise 完成后才建立同步，保留超时和关闭取消检查；复测不再发生该重置。未修改原生批注回调，没有覆盖 PDFView._setState。此证据不能证明此前用户报告的窗口卡顿同因，也不宣称已修复该卡顿。

调试监听器曾在测试销毁译文后清理，报 can't access dead object，已调整并移除临时事件栈观察。旧模式测试用全局 states.size==0 检查单个标签，另一个合法对照标签导致误失败；改为检查当前标签无 state，仍检查窗格和队列清理。首次多会话环境下旧滚动采样 P95=102ms，超过门槛；保留失败。按原单会话条件关闭其他测试对照后 P95=98ms，未放宽门槛，不承诺多会话性能。
