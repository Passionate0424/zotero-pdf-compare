## 用户反馈与根因证据

现象：非操作侧跟随不顺；分隔条首次拖动向右跳；原文切译文短暂先出现对照。

直接证据来自同一公开 19 页原/译文的原生测试接口：

```json
{
  "beforeDrag": {"left": 843, "right": 843},
  "afterDraggingLeft50px": {"left": 1103.15, "right": 582.85},
  "requestedLeftRatio": 0.47165,
  "computedLeftFlex": "1 1 0%",
  "visibleCompareSamplesDuringTranslationSwitch": 35
}
```

原生 XUL browser 的 flex="1" 属性覆盖 CSS，连内联 !important 也无效；仅移除该属性后，实际 computed flex 变为设定比例，构成干预证据。旧分隔条测试只检查 state.ratio，没检查最终宽度，因此漏掉了这项缺陷。译文初始化使用默认可见对照布局，异步加载完成后才隐藏原文，产生可见中间态。旧同步使用 24ms 偏移轮询再叠加 12ms 合并等待，密集滚动被合并为较稀疏的更新。

## 修复和复验

检查点 65f66af4623578f400606281535f93155078f5d5。改动范围：addon/src/main.js、addon/src/scroll-sync.js；测试另增观察点。

第一轮：内联 !important 未覆盖 XUL 属性，宽度仍为 1124/562；只用逐帧更新加 80ms 后备，在后台窗口退化至约 93ms 更新间隔。按检查点还原这两个文件，保留失败证据，未将这一轮视为修复。

第二轮：对照期间暂时移除原生 flex 属性，退出时原样恢复；按指针相对位移拖动，每次进入对照恢复 50/50，双击可均分。直接切译文时，在隐藏覆盖层中按最终单栏尺寸初始化，原文保留到译文就绪再替换。联动使用应用窗口逐帧时钟，后台使用及时的双偏移采样，取消额外合并等待；退出时清理逐帧回调、计时器和监听器。

同样的两侧各 60 次密集变化：旧版跟随更新 33/31 次，平均间隔 31.53/31.17ms；修复版 60/60 次，平均 15.73/15.44ms。采用相同原生脚本与正常时钟，性能区间不强制推进绘制。此为滚动偏移更新测量，**不是屏幕呈现帧率或人工流畅度评分**。

新交互回归 9/9：初始均分、首次移动无跳变、50px 拖动对应宽度变化、重新进入均分、无可见中间对照、原生属性恢复、宿主保留、两侧密集输入跟随。原生批注回归 10/10；20 次模式切换场景 7/7；导航/事件与逐帧清理 7/7；38 次页位置和 120 次内部响应采样通过，P95 48ms、最大非夹取比例误差 0.00131546。

完整尺寸及 1280 宽窄窗截图复核：原文原生工具和批注保留、译文只读、按钮可达。批注侧栏会占用原文栏内部空间，外框均分不代表正文可视区域相等。图片型译文的暗色对比度和原有公式裁切仍是已知限制。
