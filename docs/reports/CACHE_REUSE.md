# 译文阅读器复用检查点

2026-11-02，独立开发版 0.3.2，Zotero 10.0.7 / Windows / DPR 1.25。保留原文原生宿主及批注，不修改 Zotero 本体，不安装正式配置。

## 实现

此前切回原文会调用 restore，销毁译文 PDF 阅读器，下一次必须重建。现在原文模式保留最近一个隐藏译文，显示模式切换复用同一 browser 和内部 reader；隐藏时销毁滚动/缩放同步对象，移除同步监听器、计时器和逐帧回调，停用译文 docShell。重新显示只重建轻量同步对象。必要的关闭观察器保留。

最多一个**隐藏**缓存；其他正在显示的对照各有自己的生命周期。配对改变、文件路径/大小/修改时间变化、关闭文献和禁用插件均释放相应缓存。真实文件修改时间与关闭另一篇 PDF 的测试验证了失效及释放，不只检查模拟计数。

首次打开译文时在完整单栏覆盖层中初始化，原文在后方维持有效布局，直至两侧初始化完成；避免初始化时原文已隐藏，也不显示中间对照。恢复原文调用原生阅读器活动更新。修正单栏剩余 flex=0.5 导致只占半宽的问题。缓存后原文继续翻页，再切译文按原文当前页定位，不沿用隐藏译文的旧控制侧。

## 性能与内存

公开 19 页译文约 16 MB。最终构建一轮首次切换 895ms；之后 4 次为 17、11、14、11ms，确认复用相同 browsingContext。初始化完成后的计时使用正常时钟，没有推进绘制；不是系统输入到屏幕呈现的延迟。另一轮强制每次释放重建的对照及多轮结果见 CACHE_REUSE.json。不能把仅 4 个后续样本当作 P95 或所有机器的保证。

测试窗口被遮挡时，首次 PDF 初始化需要绘制准备。测试驱动对五个相关窗口（应用、原文工具栏、原文 PDF、译文工具栏、译文 PDF）临时推进刷新，结束后恢复正常；仅首次加载阶段使用，后续缓存切换和空闲检查不使用。冷加载数字含这项准备，不作为纯 CPU 或真实呈现性能。早期未完整准备原文 PDF 窗口的脚本曾出现初始化超时，保留为失败。

同一测试进程 GC 后的快照（含其他标签页及原生缓存）：

| 阶段 | 驻留内存 bytes | 堆分配 bytes |
| --- | ---: | ---: |
| 无插件译文缓存 | 924,909,568 | 202,101,856 |
| 保留一份隐藏译文 | 993,140,736 | 324,379,616 |
| 释放缓存后 | 809,627,648 | 163,969,280 |

缓存期间驻留快照增加约 65.07 MiB，释放后回落；GC 同时回收了其他对象，不能把整段差额精确归为该文件或推算每篇占用。没有承诺零内存增长、所有后台 CPU 为零或释放后系统立即归还所有内存。

## 验证与边界

- 单元 41/41。
- 缓存生命周期 12/12：同一个 reader/browser、隐藏停用、计时器/监听器清理、原生布局恢复、空闲无同步写入、恢复同步、后续切换小于 250ms、真实文件修改触发失效、至多一个隐藏缓存、关闭释放、批注原附件和位置不变。
- 区域同步/左右互换 21/21；原生批注 10/10；20 次模式切换场景 8/8；页数不匹配和更换译文 5/5；禁用重启用 8/8；原生导航/清理 7/7。原文第 6 页切译文检查和单栏满宽检查通过。
- 实际重启后左右顺序、缩放开关、原文可写 3/3；重启后再次确认缓存复用，首次 979ms，后续 11–16ms。该重启验证的候选构建与最终构建只差后续阅读位置映射修复；最终构建另行通过位置和组合回归。
- 原文、译文、对照三张真实窗口截图已复核；原文原生工具及高亮保留，原文模式隐藏译文，不留半栏占位。

## 调试负结果

隐藏 XUL 窗格曾实测 0×0，补外层尺寸并不足以解决就绪等待；透明度干预也未解决。最终让两侧在首次初始化时具有有效布局，并修正测试驱动遗漏的原文 PDF 刷新窗口，未绕过原生初始化或伪造成功。曾尝试在诊断脚本直接改 docShell.isActive，被平台拒绝，未采用到产品。

页数不匹配测试失败后曾留下两页译文配对，干扰后续测试；已恢复登记的 19 页样本，并加入 finally 恢复配对。缓存保留各阅读器设置后，旧左右互换测试只改全局默认值，导致起始方向不符；测试现在先释放该文献缓存再设置起始值。程序化滚动与缩放组合测试显式更新原生 PDFViewer 的位置状态，避免在原生尚未处理滚动帧时立即缩放；未手动调用插件对齐函数来满足断言。

单栏半宽复现为 614.3/1228.6px，修复后占满 1228.6px。阅读位置复现为原文 pageIndex=5、缓存译文仍 pageIndex=0；修复后按当前原文定位，独立回归通过。
